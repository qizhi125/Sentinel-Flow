# ADR 0001：采用架构决策记录（ADR）系统

## 状态

已采纳（2026-06-21）

## 上下文

Sentinel-Flow 是一个 C++/Go/eBPF 混合系统，涉及多个架构层面的关键权衡：无锁并发模型选择、eBPF 后端集成策略、CGO 边界设计、OT 协议检测深度等。随着项目从 Phase 0 基准确立迈向 Phase 1–4 功能开发，需要一种轻量级、可追溯的机制来记录关键架构决策及其理由。

## 决策

采用 **Michael Nygard 风格的架构决策记录（ADR）** 系统，存储于 `docs/adrs/` 目录。

每条 ADR 包含以下章节：
1. **状态**：Proposed / Accepted / Deprecated / Superseded
2. **上下文**：触发此决策的技术背景和约束条件
3. **决策**：明确陈述所选择的方案
4. **后果**：采纳此决策带来的正面影响、负面影响和后续行动项

ADR 为不可变记录。不修改已存 ADR；通过新建 ADR 并标注 "Supersedes ADR-NNNN" 来推翻旧决策。

## 后果

- **正面**：架构决策可追溯、可审查；新贡献者可理解项目为何如此设计
- **正面**：轻量级 — Markdown 文件，零工具依赖，可直接在 Git 中版本控制
- **负面**：需在每次重大架构变更时额外编写 ADR 文档
- **行动项**：所有后续 Phase 中的重大架构决策必须创建对应 ADR
